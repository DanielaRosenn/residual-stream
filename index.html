    The Residual Stream

    A language model does one thing: given some text, it guesses the next piece. Everything else — chat, code, reasoning, agents — is that guess, repeated. This site takes the machine apart, layer by layer, until nothing about it is mysterious.

    The whole journey, in one line

    Follow one piece of text through the model. Each stop is a chapter below.

    1. Text is split into tokens
    2. Tokens become vectors
    3. Position is mixed in
    4. Attention lets tokens share information
    5. Blocks repeat this dozens of times
    6. Logits become a choice
    7. The new token is appended, and the loop runs again

    Layer 1

    How it began

    The transformer did not arrive from nowhere. It is the answer to a problem that took sixty years to state precisely: how do you let a machine use all of its context, at once, at scale? The story has three acts. Pick one.

      The one-paragraph version. Neural networks learned to represent words as vectors (2013). Recurrent networks learned to translate by squeezing a whole sentence into one vector (2014). Attention removed the squeeze by letting the decoder look back at every word (2014). The transformer threw recurrence away entirely and kept only attention (2017) — and that design turned out to scale almost without limit.

      Layer 2

      Text becomes tokens

      A model can't read letters or words directly; it reads integers from a fixed vocabulary. Characters keep the vocabulary tiny but make sequences very long. Whole words make sequences short, but the vocabulary explodes and any new word is unknown. Byte-Pair Encoding (BPE) splits the difference: start from characters, then repeatedly merge the most frequent adjacent pair into a new token.

      Below, BPE is genuinely trained on this site's sample text. Slide the number of merges and watch common words fuse into single tokens while rare words stay in pieces.

        Why this matters in practice

        Pricing, context limits and latency are all counted in tokens, not words. English averages roughly four characters per token in modern tokenizers. Languages that are underrepresented in a tokenizer's training data — Hebrew is a classic example — often need noticeably more tokens for the same meaning, so they cost more and fit less into the context window.

        Strange behaviour, explained

        Ask a model how many r's are in "strawberry" and it may stumble: it never saw letters, only chunks like str aw berry. Arithmetic on long numbers suffers for the same reason. Production tokenizers work on bytes rather than characters, so every possible input — emoji, code, any script — can be encoded.

        Layer 3

        Tokens become vectors

        Each token ID indexes a row in a large learned table, the embedding matrix. The row is a vector — 768 numbers in GPT-2 small, 12,288 in GPT-3. Nobody hand-designs these numbers; training nudges them until tokens used in similar ways end up near each other. Directions in this space start to mean things.

        Real embeddings live in thousands of dimensions, and a single direction rarely means exactly one human concept. But the core idea holds: meaning is position, and similarity is measured with a dot product. That dot product is about to become the heart of attention.

        Layer 4

        Where is each token?

        Attention, as you'll see next, treats its input as a set: shuffle the tokens and, without extra help, every token computes the same result. "Dog bites man" and "man bites dog" would look identical. So the model must be told where each token sits.

        The original transformer added a fixed pattern of sines and cosines to each embedding. Each pair of dimensions oscillates at a different frequency — fast ones distinguish neighbours, slow ones encode coarse position, like the hands of a clock.

        What modern models use: RoPE

        Most current LLMs use rotary position embeddings (RoPE, 2021). Instead of adding a pattern, they rotate pairs of dimensions of the query and key vectors by an angle proportional to position. When a query and a key are compared, only the difference of their angles survives, so the model sees relative distance directly. Move the slider: each circle is one dimension pair, turning at its own speed.

        Layer 5

        Attention: tokens talking to tokens

        Here is the idea that changed everything. Every token turns its vector into three new vectors, each through its own learned matrix:

        • Query — what am I looking for?
        • Key — what do I offer, as seen by others?
        • Value — what will I hand over if someone attends to me?

        Each token compares its query with every earlier token's key using a dot product. A high score means relevant. Softmax turns the scores into weights that sum to one, and the token's output is the weighted average of the values. It is a soft, differentiable dictionary lookup — and because every pair is compared in one matrix multiplication, it runs in parallel on a GPU, which recurrent networks never could.

        See it resolve a pronoun

        In "The animal didn't cross the street because it was too tired", what does it refer to? Change the last word to wide and the answer flips. Click a token on the left to see where it looks. Each head is one independent attention pattern; a layer runs many in parallel.

        The full matrix: row is the token doing the looking, column is the token looked at. The empty upper triangle is the causal mask — a token can never look at the future.

        These head patterns are hand-set to mirror ones researchers repeatedly find in trained models: previous-token heads, coreference heads, and "attention sinks" on the first token. In a real model they emerge from training; nobody writes them.

        Now do the maths yourself

        Four tokens, tiny dimensions, real numbers. Step through scaled dot-product attention exactly as it runs on a GPU:

        Attention(Q, K, V) = softmax( QKᵀ / √dk + mask ) · V

        Why divide by √dk?

        The dot product of two random vectors with dk dimensions grows like √dk. Large scores push softmax into a near one-hot spike where gradients vanish and learning stalls. Dividing keeps scores in a healthy range. Drag the sharpness slider above to feel what oversized scores do.

        Why many heads?

        One softmax can only average in one way. Splitting the vector into, say, 32 heads of 128 dimensions lets a layer track syntax, coreference, position and topic at the same time. The heads' outputs are concatenated and mixed back together by an output matrix WO.

        The cost. Comparing every token with every other is O(n²) in sequence length: doubling the context quadruples attention work. Much of modern LLM engineering — FlashAttention, sliding windows, KV-cache compression, linear and hybrid attention — exists to fight this square.

        Layer 6

        The block, and the stream it sits on

        A transformer is one block, stacked. GPT-2 small has 12; GPT-3 has 96. The most useful mental model is the one this site is named after: the residual stream. Each token has a vector flowing straight up through the network. Every component reads from the stream, computes something, and adds its result back. Nothing overwrites; everything accumulates.

        One token's vector (8 of its dimensions) as it moves through the block. Faint bars show the vector at the previous stage.

        Attention moves information

        Attention is the only place tokens interact. It copies information between positions: "the subject of this verb is over there", "this name appeared earlier".

        The MLP stores knowledge

        The feed-forward network works on each token alone. It expands the vector about four times, applies a nonlinearity, and projects back. Roughly two thirds of a dense model's parameters live here, and interpretability research suggests much factual recall happens in these layers.

        Why residual connections? Without them, a signal passing through a hundred layers is distorted beyond recovery, and gradients vanish on the way back. The idea came from computer vision — ResNet, 2015 — and it is what makes depth trainable at all. LayerNorm (today usually the cheaper RMSNorm) keeps each sublayer's input at a stable scale.

        Count the parameters yourself

        Pick a real model or set your own dimensions. The calculator uses the actual architecture formulas, including grouped-query attention and gated (SwiGLU) MLPs. It leaves out the tiny norm and bias terms.

        Layer 7

        From scores to a choice

        After the last block, the final vector of the last token is multiplied by the unembedding matrix, giving one score — a logit — for every token in the vocabulary. Softmax turns logits into probabilities. Then something has to choose. The network never decides; the sampler does, and its settings shape how the output feels as much as the model does.

        The best way to learn something new is to …

        Temperature

        Divides every logit before softmax. Below 1 sharpens the distribution toward the favourite; above 1 flattens it toward chaos. At 0 it becomes greedy decoding: always the top token, fully repeatable, often dull and prone to loops.

        Top-k and top-p

        Truncation cuts off the long tail of nonsense. Top-k keeps a fixed number of candidates. Top-p, or nucleus sampling, keeps the smallest set whose probabilities add up to p, so it adapts: narrow when the model is sure, wide when it isn't.

        The chosen token is appended to the input, and the whole forward pass runs again for the next one. That loop is autoregressive generation, and it is why answers stream in word by word.

        Layer 8

        How it learns

        Pretraining has a beautifully simple objective. Show the model real text, ask it for a probability distribution over the next token at every position, and measure how surprised it was by what actually came next: the cross-entropy loss, −log p(correct token). Backpropagation computes how every parameter should move to reduce that surprise, and gradient descent moves it a little. Repeat for trillions of tokens.

        A sample from the model right now: —

        A bigram model only ever sees one character of context, so its loss floor is high. A transformer sees thousands of tokens and has billions of parameters, so it can push the loss much lower — and to get there it has to learn grammar, facts and patterns of reasoning, because those are what make text predictable. Scaling laws (2020) showed that loss falls smoothly and predictably as parameters, data and compute grow. Chinchilla (2022) showed most models of the time were undertrained, and that data should grow alongside model size — roughly 20 tokens per parameter for compute-optimal training.

        From text predictor to assistant

        A pretrained model is a brilliant autocomplete, not an assistant. Ask it a question and it may continue with three more questions. Post-training reshapes its behaviour, in stages:

        1. Next-token prediction over a huge, filtered corpus. Nearly all knowledge and capability comes from here, and nearly all the compute goes here. The output is a "base model".

        2. Train on high-quality demonstrations of an assistant behaving well: following instructions, answering clearly, using a chat format. Same loss, different data. It teaches format and persona far more than new knowledge.

        3. Humans — or a model guided by written principles — compare pairs of answers. A reward model learns those preferences, and reinforcement learning pushes the model toward preferred answers (RLHF, popularised by InstructGPT in 2022). DPO (2023) reaches a similar goal with a simpler loss and no separate RL loop.

        4. Give the model problems whose answers can be checked — tests pass, the maths is right, the task completes — and reward success. Models learn to think at length before answering, to backtrack and to verify. This is how reasoning models (from 2024 on) were built, and it is increasingly where capability gains come from.

        Layer 9

        What changed since 2017

        A model built today would be recognisable to the authors of the original paper, but almost every component has been tuned. These are the ideas that matter most when you build on top of LLMs.

        The KV cache

        When generating token 500, the keys and values of tokens 1–499 haven't changed — the causal mask guarantees it. So inference stores them and computes K and V only for the new token, turning repeated quadratic work into one new row per step. The same idea is why prompt caching makes repeated long prompts cheap. The catch: the cache eats GPU memory, and that memory, rather than compute, often limits how many users a server can handle at once.

        Each row is a generation step; each cell is a token whose key and value exist at that step. Green cells are computed fresh in that step, faint ones are read from the cache.

        Mixture of experts

        Instead of one big MLP, an MoE layer holds many smaller "expert" MLPs and a router that sends each token to just a few of them. Total parameters grow enormously while compute per token stays modest. Kimi K2, an open-weight model released in July 2025, has about a trillion parameters but activates only 32 billion for each token. Pick a token and watch the router choose.

        Long context

        Context windows grew from 512 tokens in the original GPT models to a million and more. It took RoPE scaling tricks, FlashAttention (exact attention computed without ever writing the full n×n matrix to slow memory), grouped-query attention to shrink the KV cache, and hybrid designs that interleave cheap linear-attention layers with full attention. A long window is not the same as using it well: recall from the middle of a huge context remains a weak spot.

        Reasoning and test-time compute

        Chain-of-thought prompting (2022) showed that letting a model write out intermediate steps improves its answers. Reasoning models made this native: trained with RL to deliberate at length before answering. Accuracy now scales with how long a model thinks, not only with its size — which is why a "thinking budget" became a product setting.

        RAG and tools

        A model's knowledge is frozen at training time and stored lossily. Retrieval-augmented generation puts fresh, relevant documents into the context instead. Tool use goes further: the model emits a structured call, your code runs it, and the result comes back as more tokens. Standards like the Model Context Protocol (2024) make tools pluggable across applications.

        Agents are a loop

        An agent is the autoregressive loop, one level up: think, call a tool, read the result, decide again — until the task is done. Orchestration frameworks mostly manage this loop's state, its context window, and the points where a human should approve the next step. Everything on this page is still running underneath every one of those steps — Layer 11 takes the loop apart.

        Layer 10

        Looking inside the box

        We know exactly what a transformer computes — every multiplication is right there. What we don't know is why those billions of numbers produce the behaviour they do. Interpretability is the science of reading the computation: finding the concepts a model represents, and the circuits that connect them. It matters for safety, for debugging, and for trusting what a model tells you about itself.

        Watch a prediction form, layer by layer

        The logit lens is the simplest trick in the book. Take the residual stream partway through the network, apply the final norm and unembedding early, and ask: if the model had to answer now, what would it say? Because every layer adds to the same stream, the guess sharpens as you climb.

        The Eiffel Tower is located in the city of …

        Numbers are illustrative, shaped like published logit-lens results on GPT-2-sized models: generic tokens early, related concepts in the middle, the answer late.

        Superposition: more concepts than dimensions

        If each neuron meant one thing, we could just read them off. They don't. A model has to represent far more concepts than it has dimensions, so it packs them in at angles that are almost — but not quite — perpendicular. This works because most concepts are rarely active at the same time. When two are, they leak into each other. This is superposition, and it's why single neurons look like a jumble of unrelated meanings.

        Here five features share a two-dimensional space, exactly as in Anthropic's "Toy Models of Superposition". Switch features on and watch what the model reads back. One at a time works. Pick two that aren't neighbours, and a third, inactive feature lights up — interference.

        Real computation: hidden = W·x (5 features → 2 dimensions), read-back = ReLU(Wᵀ·hidden − 0.35). The bias and ReLU filter out small leaks; large ones get through.

        Finding the features: sparse autoencoders

        If concepts are directions packed in superposition, we need a way to unpack them. A sparse autoencoder (SAE) is trained to rewrite each activation as a combination of a few directions from a much larger dictionary — millions of candidate features instead of thousands of neurons. In 2024, Anthropic's "Scaling Monosemanticity" applied this to a production model, Claude 3 Sonnet, and found millions of features that are often strikingly clean: the Golden Gate Bridge, code bugs, sycophantic praise, deception. Many are multilingual and multimodal — the same feature fires for a concept across languages and in images.

        Steering: turning a feature up

        A feature is a direction, so you can push the residual stream along it and watch behaviour change. Anthropic did exactly this with "Golden Gate Claude": with the bridge feature clamped high, the model brought every conversation back to the bridge, and even described itself as the bridge. Turn the dial below. The maths is real: each candidate's logit rises in proportion to how well its unembedding aligns with the feature direction.

        My favourite place to visit is …

        logitᵢ = baseᵢ + strength × (unembeddingᵢ · feature). Base logits, alignments and the sample continuations are made up for illustration; the mechanism is the one used in real steering experiments.

        Activation patching: finding where an answer lives

        Seeing a feature isn't proof it matters. Activation patching tests cause and effect. Run the model twice: on a clean prompt, and on a corrupted one that changes the answer. Then take one activation from the clean run — one layer, one position — paste it into the corrupted run, and see how much of the clean answer comes back. Where patching restores the answer, that activation carries the information.

        Circuits: how features connect

        Features are the variables; circuits are the algorithm. Early wins came from small models. Induction heads (2022) — a previous-token head feeding a second head — implement "find where this token appeared before and copy what came next", and they appear abruptly during training at the same moment in-context learning improves. The indirect object identification circuit in GPT-2 small (2022) mapped around two dozen heads that work out who received what in "When Mary and John went to the store, John gave a drink to…".

        In 2025 Anthropic's attribution graphs traced circuits inside Claude 3.5 Haiku on real prompts. Among the findings: asked for the capital of the state containing Dallas, the model internally represents "Texas" as an intermediate step before "Austin"; writing a rhyming couplet, it picks the rhyme word before composing the line that leads to it; and for mental arithmetic it runs a rough-magnitude path and an exact-last-digit path in parallel — while describing, if asked, the carry-the-one method it learned from text.

        Honest limits. Interpretability is young. Anthropic reported that its attribution graphs gave satisfying insight for only about a quarter of the prompts it tried. SAE features are partial and sometimes split or merge concepts arbitrarily; Google DeepMind's team found SAEs underperformed simple linear probes on some practical tasks and shifted its focus. We can read pieces of the computation, not yet the whole of it.

        Why a builder should care

        A model's explanation of its own reasoning is generated text, not a readout of its internals — the arithmetic example shows they can differ. That's a reason to judge agents by behaviour and evals, not by their self-reports. Interpretability tools are also becoming practical: linear probes on activations can flag things like a model being unsure or a prompt being an attack, cheaply, before any text is generated.

        The tools

        The building blocks you've seen on this page are the same ones researchers use: the residual stream as a shared workspace, attention patterns, the logit lens, activation patching (swap one activation from a different prompt and see if the answer flips), probes, SAEs and steering. Open-source libraries such as TransformerLens and public feature explorers like Neuronpedia let you try them on real open-weight models.

        Layer 11

        Agents: the loop, one level up

        Nothing new happens inside the model when it "uses a tool". It is still predicting tokens. The tool definitions are text in the context. The model has learned, in post-training, that when a tool would help it should emit a call in a strict structured format. Your code — not the model — parses that call, runs the real function, and appends the result to the context as more tokens. Then the model predicts again. An agent is that cycle repeated until the task is done.

        Step through a real-shaped agent run

        The task: "Find this week's most common customer complaint and draft a reply to the worst case." Each click adds one message to the context. Watch two things: the context grows with every tool result, and every model call re-reads all of it.

          Token counts are realistic orders of magnitude for a run like this. Cached input is billed at a tenth of the normal input price here, which is what some providers charge for cache reads; others discount less.

          Workflows or agents?

          A workflow runs the model through steps your code fixes in advance: classify, then retrieve, then draft. An agent lets the model choose the next step itself. Workflows are cheaper, faster and easier to test; agents handle open-ended tasks where the path can't be predicted. A good default is the simplest structure that works, adding autonomy only where it clearly pays for itself.

          MCP: a standard plug for tools

          The Model Context Protocol, open-sourced by Anthropic in November 2024, standardises how an application exposes tools, resources and prompt templates to a model. Build a server once — for a ticketing system, a database, a code repo — and any MCP-compatible client can use it. Under the hood it is still the same thing: tool descriptions become tokens, calls come back as structured output.

          Why long tasks are hard: errors compound

          If every step succeeds independently with probability p, a task of n steps succeeds with probability pⁿ. Drag the sliders. This is why agents need steps that check their own work, retries, and good tools that fail loudly — and why a model that is 99% reliable per step behaves very differently from one that is 95% reliable.

          A simplification: real errors aren't independent, and an agent that verifies and backtracks can recover from mistakes. That recovery is exactly what reasoning models are trained to do.

          Context engineering

          The context window is the agent's only working memory, and everything in it costs tokens and attention. Practical agents trim tool results to what matters, summarise or compact old turns, hand self-contained subtasks to sub-agents with fresh contexts, and keep durable notes in files or a memory store rather than in the conversation. Put stable content — system prompt, tool definitions — first, so caching can reuse it.

          Safety in the loop

          Tool results are untrusted input. A web page or an email can contain text written to hijack the agent — prompt injection. Defences are architectural: give each tool the least privilege it needs, treat retrieved text as data rather than instructions, log every call, and require a human approval step before anything irreversible — sending, paying, deleting, deploying.
